01

成果物ではなく、成立過程まで残す

Chronicle Stackの中心価値は「再構成可能性」にある。

AIを利用した執筆、調査、設計、開発では、完成した成果物だけが残り、その成果物がどの問い、資料、指示、判断、修正を経て成立したのかが失われやすい。Chronicle Stackは最終結果だけでなく、そこへ至る過程を監査・継承可能な来歴として保持する。

Chronicle Stackは、人間とAIの共同作業から生じた文脈・判断・生成物・意味変化の来歴を、人間が保持し、検証し、選び直せるようにする基盤である。
02

何が失われているのか

完成物だけでは、判断の妥当性も意味の変化も再現できない。

  • どの問いや文脈から始まったか
  • どの資料・情報源を参照したか
  • 人間が何を指示したか
  • AIが何を提案したか
  • どの案を採用・棄却・保留したか
  • 修正が意味をどう変えたか
  • 人間が最終的に何を判断したか
  • 未確認のAI解釈がいつ混入したか
03

全体構造

一次記録と派生面を分離し、正本の位置を曖昧にしない。

図1：Chronicle Stack v2.2.0を基準とした現在の主要構造と、境界付きの将来拡張。

Primary record

正本はchronicle.jsonl

.chronicle/chronicle.jsonlを安定した追記型の一次記録とする。状態変更はChronicle Eventを経由し、履歴の基点を一本化する。

Derived surfaces

Index・UI・Exportは再構築可能

検索用Index、read-only UI、YAML・HTML・Graph出力は補助面であり、一次記録から再生成できる。表示や検索の都合を正本へ昇格させない。

04

設計原則

便利さより先に、文脈と判断の主権を守る。

01Local-first

記録の正本を利用者側に置き、特定のクラウドAIメモリへ文脈を委ねない。

02文脈主権

人間が文脈を確認・選択・訂正・除外できる。AI解釈を本人の事実へ自動昇格させない。

03人間による最終判断

AI投入や外部共有はpreviewを経た明示操作を基本とし、自動適用を避ける。

04意味差分 ΔM

文字列差分だけでなく、意図や設計思想の保存・変換・補完・逸脱をRDEで記録する。

05境界の可視化

include・warn・excludeにより文脈選択を支援する。ただし現段階ではアクセス制御ではない。

06控えめな主張

出所記録は真実性の証明ではなく、RDEは正しさの証明ではない。機能と権威を混同しない。

05

主要な記録対象

共同作業を、意味の異なるオブジェクトとして分離する。

オブジェクト役割
Context作業に用いる文脈、その有効範囲、可視性、出所を記録する。
Artifact文書、コード、仕様などの成果物とバージョンを管理する。
Decision案の採用、棄却、保留と、その理由を成果物へ関連付ける。
RDE Diff Record変更による意味差分を構造化して記録する。正しさの証明ではない。
Source Provenance情報や生成物の出所を記録する。真実性の暗号学的証明ではない。
Boundary Rule文脈を含める、警告する、除外するための判断材料を与える。
Audit / Lifecycle検査、共有、保持、封印、減衰、撤回などの状態変化を扱う。
06

現在の実装境界

将来構想を、実装済みの能力として語らない。

現在の主要機能

  • local-firstの追記型記録
  • CLIと派生Index
  • Artifact・Decision・RDE
  • read-only local UI
  • Audit・Boundary・Lifecycle
  • ExportとFederationの基礎面

現在は該当しないもの

  • クラウド型AIメモリ
  • LLMエージェント実行基盤
  • 汎用ベクトルDB・完成済みGraphRAG
  • 正しさの自動証明
  • 書き込み可能な常駐Webサービス
  • 完成済みネットワーク型分散連合
07

ZYX関連システムとの関係

Chronicle Stackは共通来歴基盤であり、各システムを内部モジュールとして包含しない。

システムChronicle Stackとの関係
Ayane（綾音）現在の作業に必要な文脈を保持・再構成し、必要な記録をChronicle Stackと交換する。
Sayane（紗綾音）人間の意図とAI生成物の意味差分・逸脱を監査し、RDE記録へ接続する。
Kazane（風音）業務意図を実行へ編成し、その判断や成果をChronicle Stackへ記録する。
Chronicle Stack各システムから独立して、文脈・判断・成果物・意味変化を来歴として保持する。

Core proposition

守るのはAIの回答ではなく、
人間とAIが考え、選び、修正した来歴である。

成果物だけでなく、問い、文脈、判断、反論、出所、意味差分を再構成可能な形で残す。Chronicle Stackは、人間や組織がAI時代にも自らの記憶と判断を失わないための基盤を形成する。
