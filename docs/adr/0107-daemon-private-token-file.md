# ADR-0107: Private daemon token file lifecycle

Status: Accepted
Date: 2026-09-15
Related: ADR-0104, ADR-0106

## Context and decision

CY-1 removes daemon credentials from argv and public startup metadata. The unreleased daemon
MVP's `--session-token` option is removed rather than deprecated: retaining it cannot satisfy the
no-argv-secret acceptance criterion. Existing clients migrate to `--token-file PATH`, which names
an output file, not an input credential. The default is `<root>/.chronicle/daemon.token`.

On foreground startup the daemon generates 32 cryptographically random bytes encoded as URL-safe
text (256 bits at generation). It exclusively creates a new regular file with mode exactly 0600,
rejects existing files even with 0600 permissions, and rejects symlinks, including parent symlinks.
File creation precedes binding and failures abort startup. No credentials are printed, logged,
serialized as metadata, or included in dataclass representations. `--json` remains metadata-only:
it neither starts a server nor issues a token. It may disclose the non-secret token file path.
Startup metadata declares `startup_schema_version=chronicle-daemon-startup/v2`; the API payload
`schema_version` stays unchanged. No adapter restores the credential-disclosing startup shape.

Programmatic token injection must use 43–128 URL-safe ASCII characters, at least 16 distinct
characters and at least 192 bits of empirical character-distribution entropy. These are rejection
heuristics, not a proof that caller-supplied text was randomly generated. Production CLI tokens
are always generated by `secrets`, never accepted from argv or an existing file.

The file is removed on normal shutdown, Ctrl-C, SIGTERM, and bind/serve errors. Cleanup compares
file identity and does not unlink a replacement. SIGKILL or power failure cannot run cleanup;
operators must verify the daemon stopped before removing a stale credential and restarting.
This is a single-operator boundary, not protection from hostile same-UID processes.

## Alternatives

- Retain argv credentials with a warning: rejected because they remain visible in process arguments.
- Stdin/inherited descriptor input: deferred; a generated private file gives local clients an explicit
  credential location and requires no shell secret expansion.
- Reuse an existing token file: rejected; exclusive creation prevents accidental session reuse.

## Verification

Test weak credentials, existing modes, symlinks, exclusive-create collisions, restrictive umask,
metadata/stdout secrecy, normal/error cleanup, and replacement preservation. Run socket regressions,
the full suite, lint and canonical local CI. Token value must be read from the private file into a
client's memory and placed in the existing daemon authentication header, never a command argument.

## T-RDE

- Preserved: loopback non-browser transport, authentication header, Core-mediated writes and JSONL.
- Transformed: terminal/argv credential delivery becomes exclusive generated file delivery.
- Supplemented: entropy screening, cleanup, safe errors, metadata-only non-issuance.
- Unresolved: same-UID isolation, abrupt termination, CY-2 capability/resource authorization.
- Deviation risks: treating permission bits or character entropy as proof of caller identity.
- Next update policy: reassess on multi-user support, remote access or a new credential consumer.
